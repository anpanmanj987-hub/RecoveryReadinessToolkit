Windows / Python 3.13.15 / Node.js 24.19.0 / PyYAML 6.0.3 / Playwright 1.64.0 とインストール済みMicrosoft Edgeで検証しました。元アーカイブの95テストは成功し、初回は任意依存PyYAMLの1件がスキップされました。PyYAMLを追加し、下記の回帰テストを先に失敗させてから修正しています。

## 再現して修正した問題

| 問題 | 再現方法・原因 | 修正 |
|---|---|---|
| WindowsのCSVレポートに空行が入る | `check`のCSVファイルにCRCRLFが含まれる。`csv.writer`のCRLFにテキスト書き込みの改行変換が重なっていた | CSVの書き込み時に改行変換を無効化 |
| JSONの単独サロゲートを含むキーでHTTPハンドラが落ちる | `/api/validate`へ`model_json`が`{"\ud800":true}`のリクエストを送る。値だけを検証し、未知キーのエラーメッセージをUTF-8に変換できなかった。重複キーでも再現 | オブジェクトキーも検証し、重複検出より前にもチェック |
| ASCII以外のトークンでHTTPハンドラが落ちる | `X-CRC-Token: é`で`/api/bootstrap`を要求すると`compare_digest`がTypeErrorを出す | ASCII確認後に比較し、不正なトークンへ403を返す |
| Windowsで拒否したPOSTのエラー応答がTCP resetで失われる | 64KiBの`text/plain`本文を送る。未読本文があるソケットを閉じると、415応答を受信する前に接続がリセットされた。既存のOrigin/Content-Typeテストでも断続的に発生 | 応答を先に送信し、長さが明確かつ2MiB以下の未読本文だけを既存5秒タイムアウト内で消費。上限超過や曖昧な長さは読み込まない |
| 返却したレポートの編集で後続レポートの出典が消える | `evaluate()`の返却値の`findings[0].source_ids`を変更すると、グローバルルールカタログも変わる | 返却時に出典IDリストをコピー |
| JSON反映・インポートの遅延応答で新しい入力が失われる | 反映中にJSONを再編集、テンプレートを変更、編集を破棄、または複数ファイルを逆順に完了させる | 各処理の開始時に更新番号を進め、古い応答を破棄。JSON破棄も処理を無効化 |
| 入力中に古い点検結果が表示される | フォームへ入力してフォーカスを移さない。`change`イベント前に古い結果が残り、点検中の応答も反映された | 名前、数値、日付、証跡IDを`input`時点で反映し、結果を無効化 |
| 初期カタログ取得前のテンプレート操作が例外になる | bootstrap取得を遅延させてテンプレートボタンを押す | テンプレート・インポート操作は取得完了後に有効化 |
| 任意ブラウザ試験がWindowsでUTF-8を読めない | cp932環境で`python -m tools.browser_smoke`を実行すると、保存した日本語HTMLの読込時にUnicodeDecodeError。コンポーネント試験も同じ原因 | すべての該当`read_text()`へUTF-8を指定。記録の古いデモ件数も修正 |
