# Contributing

Create a focused branch, add a failing reproduction test, make the smallest change, and run `python -m unittest discover -v`.

Rules must keep missing information distinct from failure, and must not turn communication, dependency or destructive rights into administrative control. A control path alone is not a network connection. Every positive condition requires its own evidence metadata. A known negative value without evidence remains a qualified model finding, not a verified real-world vulnerability.

For a source-driven rule change, include the official source URL, the review date, scope limitations, before/after synthetic fixtures and an explanation of whether the policy changed. Do not silently broaden provider/workload compatibility. Bump the ruleset version when semantics change. Add comparison tests so reduced scope never counts as remediation.

Only fictitious, non-sensitive examples may enter this repository. Public contribution requests must not include a customer name, subscription ID, account credentials, internal hostnames or secret material. No external telemetry or automatic cloud modifications may be added without an explicit project-level design decision.

The optional browser test uses Playwright. Core runtime does not require it. Record test environment and limitations accurately; a mocked/component browser check is not a native HTTP end-to-end test.
