# Review and regression verification — 2026-10-14

Scope: production engine, input boundary, condition fingerprints, reports, CLI,
loopback server, standalone build, supplied CI, and browser editing/persistence.
This is a local code-review/test record, not a production recovery drill or an
independent security audit. The earlier [verification record](VERIFICATION.md)
describes the original archive and remains historical.

## Reproduced issues and fixes

1. **Metadata edits invalidated unchanged exercise records.** Import a goal
   whose route is `{"ref":"a"}`, bind a passed record to the model/scenario,
   edit only its owner, and save. The checkbox editor rewrote its condition to
   `{"all":[{"ref":"a"}]}`. It also reordered conjunction children to node-list
   order and removed repeated references. The model fingerprint consequently
   changed even though dependencies did not. The editor now preserves the exact
   stored expression when the selected dependency set is unchanged. Actual
   checkbox dependency changes still produce a changed fingerprint. The new
   real-browser regression failed on the `ref` rewrite before the fix, then
   passed for single references, reordered conjunctions, and repeated references.

2. **Explicit null values bypassed the strict input contract.** For example,
   `{"schemaVersion":1,"name":"x","nodes":[{"id":"g","label":"g","kind":"goal","routes":null}],"scenarios":null}`
   was accepted and silently converted into an undefined goal with a baseline
   scenario. Null `initial`, `category`, and scenario override arrays were also
   treated as absent. These values contradict the published JSON Schema and
   can hide malformed data. Defaults now apply only to omitted fields; explicit
   null values are rejected at their field path. Six rejection regressions
   failed before the fix and passed after it. A seventh test confirms the
   documented defaults for omitted fields still work.

3. **The optional browser harness crashed with Windows text encoding.** Running
   `python tests/browser-smoke.py --browser "C:\Program Files\Google\Chrome\Application\chrome.exe"`
   on this Japanese Windows host failed at the first `Path.read_text()` with
   `UnicodeDecodeError: 'cp932' codec can't decode byte 0x94 in position 607`.
   All three HTML/JSON/CSV reads now specify UTF-8. The full harness subsequently
   passed with native HTTP navigation and native browser storage.

The standalone bundle was rebuilt from the revised source. Screenshots were
refreshed from the fictional demo during the successful browser smoke test and
visually inspected. `SHA256SUMS.txt` covers current distribution files relative
to this project directory, excluding itself; it is a change detector, not a
signature.

To run the focused browser regression, install Node Playwright separately or set

Python smoke test, install Python Playwright separately. Pass the path of an
available Chromium-family browser; no application dependency is added.
