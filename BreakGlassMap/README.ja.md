# BreakGlassMap — 復旧の「はじめの一歩」を点検するOSS

**認証基盤が停止したとき、復旧操作をどこから始められるか。**

PAM、復旧用資格情報の取得条件、手順書、保守回線、管理端末、承認者などの依存関係をモデル化し、「構成上成立」「開始不可」「情報不足」を分けて示します。

**v0.1.0-alpha.1 / MIT / ローカル動作 / LLM不要 / npm追加依存なし**

[English](README.md) · [モデル仕様](docs/MODEL.md) · [検証記録](docs/VERIFICATION.md)

## 最初に試す

ZIPを展開し、`dist/BreakGlassMap.html` をブラウザで開きます。HTMLファイル単体でも動作する構成です。会社の設定でローカルHTMLが制限される場合は、ポリシーを変更せず、利用を許可されたローカルHTTP環境などで確認してください。

Node.js 22以上がある場合のローカル起動：

```sh
npm start
```

表示された `127.0.0.1` のURLを開きます。サーバーはHTMLの配信専用で、構成ファイルのアップロード先ではありません。

初期表示は架空の「認証基盤停止」です。「復旧用資格情報はPAMの中」「PAMとオンライン手順書は認証基盤に依存」という構成で、開始不可2件・情報不足1件になります。

**「独立した復旧手段を試す」**を押すと、独立した緊急認証手段とオフライン手順書を利用可能と仮定します。結果は構成上成立2件・情報不足1件。連絡先の未確認状態や訓練記録を勝手に成功へ変更しません。「変更前に戻す」で比較前に戻せます。

この例は特定製品の実仕様や設定手順ではありません。実環境の回線、強い認証、権限、承認・監査の条件をそれぞれ確認してください。

## 自分の構成を登録する

「構成を編集」から新規モデルを作り、一つの復旧目標から始めます。条件・操作・目標を追加し、操作ごとに経路を登録します。

| 種類 | 入力する内容 |
|---|---|
| 初期条件 | 他の要素に依存せず使えると仮定する回線、端末、人、資料等。利用可能・利用不可・未確認を選ぶ |
| 操作・能力 | ログイン、資格情報取得、手順参照、切り替え操作など。必要条件を経路として登録する |
| 復旧目標 | 「認証復旧作業を開始する」「バックアップ復元を開始する」など。開始に必要な操作を登録する |

一つの経路でチェックした条件は**すべて必要（AND）**、複数の経路は**どれか一つでよい（OR）**です。より複雑な入れ子は「モデルJSON」から編集できます。入れ子を含む既存経路は、フォームでも式を保持して表示します。

依存関係のあるものを初期条件の「利用可能」としてしまうと、依存する要素の停止が反映されません。例えば「SSO後に参照する手順書」は初期条件ではなく、ログインに依存する操作として登録します。

## シナリオと判定

「障害条件を編集」で、各要素を「元の条件を使用」「強制停止」「状態不明」に設定します。シナリオ追加・削除にも対応しています。

**強制停止は分析中ずっと優先されます。** 故障した初期条件を暗黙に復旧させることはありません。復旧できる場合は、その操作と復旧後の能力を別要素にして明示してください。

| 判定 | 意味 |
|---|---|
| 構成上成立 | 申告された条件から開始経路が見つかった。実機訓練成功ではない |
| 情報不足 | 未確認条件の成立や、未定義経路の確認が必要 |
| 開始不可 | 不明条件を利用可能と仮定しても開始経路が見つからない |

図をクリックすると、担当・SYSID・必要条件・代替経路を確認できます。循環した線の存在だけで復旧不能とは決めず、独立経路の有無を考慮します。

## 訓練記録は別に管理する

要素ごとに、結果、日付、確認者、証跡の参照番号、検証したシナリオID、再確認までの日数を記録できます。初期設定の日数はツールの便宜上の90日であり、あらゆる対象に適用される規程ではありません。

実際に確認した記録を**今回の構成・指定シナリオに紐付ける**場合は、そのチェックを明示的に入れます。構成やシナリオの停止条件が変わると「構成・障害条件が変更済み」と表示し、過去の記録をそのまま有効とは扱いません。担当・表示名・補足など、構造以外の変更は紐付けを変えません。

紐付けには非暗号学的な条件指紋を用います。証跡の署名・改ざん検知・真正性の保証ではありません。記録に書いたファイルやURLの内容を取得・検証する機能もありません。

## 保存と出力

初期状態ではブラウザに自動保存しません。再読み込み・終了前に**JSON保存**を使ってください。「このブラウザに保存する」を明示的に有効化することもできます。無効化すると、このアプリが保存したデータを削除します。端末やブラウザが保存を拒否する場合は、JSONで管理してください。

出力は、構成JSON、分析結果JSON、確認・訓練チェックリストCSV、HTMLレポートです。CSVは優先度フィルターによらず全件を出力します。HTMLレポートは必要に応じてブラウザの印刷機能で利用できます。

**保存データは未暗号化です。パスワード、秘密鍵、トークンは入力しないでください。構成図・復旧経路・鍵の保管場所の記述自体も機微情報になり得るため、承認された場所に保管してください。**

## 開発・CLI

追加パッケージのインストールは不要です。

```sh
npm run build
npm test
node bin/breakglassmap.mjs validate examples/identity-outage.json
node bin/breakglassmap.mjs analyze examples/identity-outage.json --scenario identity-outage --format html --out report.html --fail-on none
```

`--out` は既存ファイルを上書きしません。明示的に上書きする場合だけ `--force` を使います。既定のCLIは開始不可で2、情報不足で3を返します。これは期待される分析結果で、ツールのクラッシュではありません。詳細は `--help` を参照してください。
